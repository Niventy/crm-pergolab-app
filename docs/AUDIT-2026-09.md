# Audit bugs & UX — CRM Pergolab

## Contexte

Le CRM a beaucoup évolué depuis le CLAUDE.md (Pennylane devis/factures, espace Clients en 3 phases, notifications, documents, configurateur sur-mesure). Alexandre connaît déjà un bug de TVA sur les factures et soupçonne d'autres problèmes (ex. pas de Kanban côté client). Objectif : audit complet du code (16 k lignes, ~75 fichiers lus intégralement), isoler les bugs réels avec preuve dans le code, puis proposer un ordre de correction.

État technique : `tsc --noEmit` et `eslint` passent sans erreur. Les bugs sont donc **fonctionnels / métier / UX**, pas des erreurs de compilation.

Livrable : ce document, puis (sur validation) les correctifs par lots.

## Plan d'action recommandé (par lots, validation entre chaque)

### Lot 1 — Argent juste (P0 TVA) — *à faire en premier*
1. **Stocker le TTC et les taux du devis** : à la création/modif (`pennylane.ts creerDevisPennylane`, `updateQuotePennylane`) écrire `devis.montant_ttc` + `devis.lignes` (jsonb : designation, HT, taux) et `leads.montant_ttc` (nouvelle migration Drizzle).
2. **Marquer le devis accepté** : `devis.accepte_at` ; à la signature (« Signée »), l'ADV choisit le devis signé (si plusieurs) → `leads.montant` / `montant_ttc` = ce devis. Corrige A6.
3. **Refaire la facturation depuis le devis accepté** (`facturation-actions.ts`) : acompte = % du TTC saisi en TTC (boutons 40 / 40 / 20 issus de `echeancierPct`), réparti **par taux** au pro-rata des lignes ; solde = TTC − acomptes ; libellés « Acompte N % sur devis N° … ». Corrige A1, A2, A7.
4. **Reste à facturer / phases** sur le TTC stocké et sur les factures `finalized` uniquement ; garde anti-doublon (facture d'acompte existante → confirmation). Corrige A3, A4.
5. `vatCode(0)` → `exempt` (ou refus explicite) ; `TVA_OPTIONS` = source unique partagée au catalogue ; **taux par défaut du devis** (20/10) appliqué aux lignes du configurateur. Corrige A5, A9.
6. `formatEuros` avec centimes pour tout ce qui est facturation ; arrondir la remise au centime avant envoi. Corrige A8.

### Lot 2 — Sécurité
1. Migration SQL : `enable row level security` + politique `authenticated` sur `factures`, `documents`, `notifications`, `taches`, `produits_catalogue`, `sur_mesure_mapping` (même modèle que `setup-rls.ts`) ; vérifier dans Supabase que la Data API n'expose rien en anon. (S1)
2. Suppression : réserver aux admins + `deleted_at` (soft delete) filtré partout ; remplacer `confirm()` par une modale. (S2)
3. `PUBLIC_PATHS` : lister les routes API publiques explicitement. (S3)

### Lot 3 — Espace Clients cohérent + Kanban client
1. **Un seul statut** : l'étape cycle 3 devient la vérité ; la phase encaissement devient un **badge** (« Acompte reçu », « Soldé ») et un filtre, plus un onglet. (B2)
2. **Kanban Clients** (`/clients` par défaut) : réutiliser `KanbanBoard` avec `stages.cycle === 3` et les leads `gagnee` ; cartes client = nom, produit, TTC, encaissé/reste, dates métré/pose, poseur. Onglets Kanban | Tableau (le tableau actuel). (B1, B5)
3. **Bascule automatique à la signature** : `updateLeadStage`/`changerEtape` → si `is_gagnee`, `stage_id` = 1ʳᵉ étape cycle 3 (« À métrer »). Corrige B3 et les pilules/cartes de la fiche.
4. Étape « Annulée » (cycle 3, `is_perdue`) + raison, visible dans le rail client. (B4)
5. Fiche client : « ← Retour aux Clients ». (U4)

### Lot 4 — Pipeline fiable
1. Remplacer les noms d'étapes codés en dur par des **clés stables** (`stages.code` : `a_traiter`, `devis_envoye`, `a_metrer`…) ; une seule fonction `statutPourStage()` partagée. (C1, C7)
2. « Devis envoyé » déclenché par l'**envoi** (Gmail / Pennylane), pas par la création ; la création journalise « Devis créé ». (C2)
3. Choix explicite de l'étape KO (Hors zone / Non qualifié / Devis refusé) avec raison. (C4)
4. Mois en Europe/Paris partout (helper unique `ymParis`). (C5)
5. `router.refresh()` après drag réussi + revalidation périodique légère (ou Supabase Realtime). (C6)
6. Commentaire optionnel mais **proposé** après un drag Kanban (toast avec champ) pour aligner les deux règles. (C3)

### Lot 5 — Dashboard juste
1. Sélecteur période sur `YYYY-MM` réel (années passées incluses), label calculé depuis la clé. (D1)
2. Objectif mensuel comparé au CA **du mois courant** quelle que soit la période affichée. (D2)
3. Fusionner `acompte` → `acompte_encaisse`, `equipe_pose` → `pose_assigned_to`, décider `adresse` vs `adresse_pose` (migration + backfill). (D3)
4. Compta : basculer sur `date_signature` (avec toggle « cohorte réception » sur Commercial). (D4)
5. Entonnoir : « Devis envoyés » = échange `devis_envoye` existant. (D5)

### Lot 6 — Éditeur de devis
1. Persister `devis.config_json` (config du configurateur + suppléments) et le recharger. (G1)
2. Refuser la modification si le devis Pennylane est signé/accepté ; « Dupliquer » comme seule voie. (G2)
3. Inputs numériques contrôlés en chaîne, clés stables (`crypto.randomUUID()`), état d'erreur PDF. (G3, G4)
4. Statut devis synchronisé (brouillon / envoyé / signé / refusé) + total /devis hors variantes et refusés. (G5)

### Lot 7 — UX transverse
Padding bas global sous la barre de recherche (U1) ; Liste en `overflow-auto` (U2) ; nav à plat avec Kanban en premier + menu mobile (U3) ; filtres Liste dans l'URL (U5) ; modales avec Échap + fermeture au clic (pas mouseDown) (U6) ; textes obsolètes (U7) ; cache court sur le fil Gmail (U8) ; factorisation `MOIS_FR`/`ouvrirDans`/`FilterSelect`/`Td` (U11) ; suppression du code mort (U12) ; **mise à jour du CLAUDE.md** (U13).

## Vérification

- **Lot 1** : scénario de bout en bout sur un lead de test — devis 2 lignes (pergola 10 %, option 20 %) + remise 5 % → TTC CRM = TTC PDF Pennylane au centime ; acompte 40 % TTC → facture brouillon Pennylane dont le TTC = 40 % du devis ; solde → TTC total − acompte ; phases Commande/Facturation/SAV correctes après saisie des encaissements ; double-clic acompte → 1 seule facture.
- **Lot 2** : `curl -H "apikey: <anon>" https://<proj>.supabase.co/rest/v1/factures` → 401/`[]` ; suppression refusée à un compte membre.
- **Lot 3** : glisser une carte sur « Signée » → disparaît du Kanban vente, apparaît dans le Kanban Clients en « À métrer », fiche avec pilules cycle 3 ; annulation possible avec raison.
- **Lot 4** : renommer une étape dans la table `stages` → Planning/devis/webhook inchangés ; lead reçu à 00h30 le 1ᵉʳ classé dans le bon mois.
- **Lot 5** : `?mois=2025-12` affiche déc. 2025 ; barre objectif ≤ 100 % en vue « Année ».
- À chaque lot : `npm run lint`, `npx tsc --noEmit`, `npm run build`, puis STOP et validation (règle du projet). Aucun commit/push sans accord explicite.
